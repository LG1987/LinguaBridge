# v0.2.0 · 版本定义与改动方案

- **版本号**：`0.2.0`（第二版）
- **上一版**：`0.1.0`（2026-10-25，扩展 + 本地引擎，P0–P3）
- **版本依据**：符合语义化版本 minor —— **向后兼容地新增一种交付形态**（DSH 原生插件），扩展与引擎的既有接口和行为不变。
- **tag**：`v0.2.0`
- **产物命名**：从本版起，发布物在文件名里带**组件标识**，避免"版本号对不上是哪个东西"：
  - `LinguaBridge-extension-0.2.0.zip` — 浏览器扩展（Chrome/Edge MV3）
  - `LinguaBridge-dsh-plugin-0.2.0.zip` — DSH 原生插件（Cordis bundle）
  - 每个产物配同名 `.json` 元数据（逐文件与整包 SHA-256）
  - v0.1.0 的历史产物保持原名 `LinguaBridge-0.1.0.zip`，不重命名（tag 与提交记录仍指向它）。

## 改动方案：RC-001 为什么选"方案 A"

RC-001 要求"输入中文、点发送后会话里是英文"。实测约束：

- 客户端**没有**提交前事件（只有 `connection/reset`、`locale/change`、`slots/changed`、`theme/change`）；
- 原生发送键**没有**公开拦截钩子；接管它需要替换 `conversation.composer`（chain 插槽），与 DSH 版本强绑定；
- 可用的稳定接口是插槽标准属性：`useInput`（读 `InputState.draft`）与 `inputActions`（`setDraft` / `persistDraft` / `submit`）。

因此本版采用 **方案 A：独立「译并发送」按钮**——点一次即完成"翻译 + 写回 + 提交"，结果为英文；代价是按的不是原生发送键。方案 B（接管原生发送）留作后续评估，需要先验证版本升级下的稳定性。

顺序上的一个关键细节：`setDraft()` 后 Lexical 的投影要下一帧才发布，直接 `submit()` 会把旧中文发出去。插件在提交前轮询"已发布草稿是否等于译文"（上限 1.5 s），再提交。

## 安装与回滚

- 扩展：解压 `LinguaBridge-extension-0.2.0.zip` → 扩展页「加载解压缩的扩展」。
- 插件：解开 `LinguaBridge-dsh-plugin-0.2.0.zip` 得到包目录，用 DSH 插件管理器以该目录安装。
- 回滚：扩展沿用上一版 zip 覆盖加载；插件在插件页停用或卸载，DSH 原生发送立即恢复。引擎与数据无 schema 变更，回滚无残留。

## 已知问题

1. Argos 属传统 NMT，长句与否定会走样（实测「不要改写实现」→ "not rewritten to be achieved"）。格式逐字保住，语义需人工扫一眼。
2. 插件目前只做中 → 英的用户输入；AI 回复译中文仍依赖浏览器扩展。
3. 插件会改写输入框草稿（这正是需求），因此草稿的历史/撤销体验与原生不同。
4. 安装插件会改动 profile，对所有会话生效。
